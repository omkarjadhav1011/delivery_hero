## The S0 game fixture (T9)

The game must exist only in memory, with no `games` row. The deploy lock and the seed command read `games` (`GameInProgressCheck`), and CI loads the seed after the stack starts, so a row in LOBBY would make the seed command refuse to run.

The open point is when the game opens:

- **A, recommended:** an `e2e`-profile-only endpoint, `POST /api/test/s0-game`. It discards any open session and opens a fresh LOBBY game with code K7PQ2M on the Quick 3-minute plan. The spec calls it before it starts, so a retry or a second local run still joins as exactly "Priya". S1-04 T6 deletes it.
- **B:** the game opens once at startup in the `e2e` profile. There's no endpoint, but a second run without restarting the backend joins as "Priya 2", and step 3 fails.
