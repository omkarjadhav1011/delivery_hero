## Report

Already in place: `AdminProperties` (bcrypt cost 12 or more, validated at startup), the `admin` `UserDetailsService`, `BCryptPasswordEncoder`, `server.servlet.session.timeout: 12h`, CSRF (`csrf.spa()`), `RateLimiter` and `RateLimitFilter` (joins), `MutableClock`, `adminPassword` in the e2e fixtures, and the copy for A-01's heading and label.

Missing: form login and its handlers, `GET /api/admin/session`, logout, the `DH_SESSION` cookie name and flags, the `UNAUTHENTICATED` code, the login limit, the login logs, the login screen and the e2e login step.

Findings that shape the design:

1. The servlet timeout counts idle time, but AC-US49-02 (log in at 09:00, act at 20:59, act again at 21:01, refused) and API 7.3's `expiresAt` need a fixed 12 hours from login. So the session stores `expiresAt` = login time plus `server.servlet.session.timeout` from the injected clock, and a filter ends the session after it. The servlet timeout stays as the backstop.
2. MockMvc doesn't produce Tomcat's session cookie, so AC-US49-04 (the cookie flags) needs a real server test (`RANDOM_PORT`), in its own class `AdminSessionCookieIT`, not in `SecurityIT`. This is recorded as a doc issue, like DI-49.
3. Login needs a CSRF token (DI-51), so the login screen calls `GET /api/admin/session` first, which is open and sets `XSRF-TOKEN`.
