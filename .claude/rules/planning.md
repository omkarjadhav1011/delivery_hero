# Planning rules

Formats, layout and procedures: `planning/CONVENTIONS.md`. Read the section you need; don't restate it. These always apply:

- Never edit `docs/` from planning work; during implementation only with the owner's approval of that specific change. Document problems go to `planning/doc-issues.md`, unknowns to `planning/open-questions.md`.
- `STATUS.md` and `COVERAGE.md` are generated by `status.py` and `trace.py`; `journal/CURRENT.md` by `journal.py`. Never edit them by hand.
- Tick a task (`- [x]`) only when it's finished and its test passes. Never remove ticked tasks, progress-log lines or journal history.
- Cite IDs and numbers from the documents or the scripts' output; never paraphrase requirements from memory.
- After changing subplans or registers, run `node planning/scripts/run.mjs validate` and `node planning/scripts/run.mjs trace`.
- `planning/` holds Markdown plus the scripts in `planning/scripts/`. After changing a script, run `python -m unittest discover planning/scripts/tests`.
